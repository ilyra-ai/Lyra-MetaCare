# API da Lyra MetaCare (Route Handlers)

Todas as rotas ficam em `src/app/api/**/route.ts` e rodam no runtime Node.js. A sessão é um cookie `httpOnly` (`lyra_metacare_session`, JWT HS256 assinado com `AUTH_SECRET`).

## Contrato comum

- **Entrada:** todo corpo JSON passa por `lerJson` (`src/lib/http/api.ts`) com um schema Zod. JSON malformado e campos inválidos respondem **400**, com a lista de campos na mensagem.
- **Erros:**
  - `HttpError` usa o status próprio (401 sem sessão, 403 sem permissão, 404 inexistente, 409 conflito, 413 arquivo grande, 415 tipo de arquivo, 503 integração não configurada).
  - Chave duplicada do MySQL vira 409; violação de tipo, nulo ou chave estrangeira vira 400.
  - Qualquer outra falha responde **500** só com a mensagem genérica da rota. O detalhe (SQL, caminho, stack) vai apenas para o log do servidor.
- **CSRF:** escrita (`POST`, `PUT`, `PATCH`, `DELETE`) vinda de outra origem responde **403** (`src/proxy.ts`); detalhes em [`seguranca.md`](./seguranca.md).
- **Limite de tentativas:** login e cadastro respondem **429** com `Retry-After` quando a janela estoura.
- **Sessão:** o JWT fica só no cookie `httpOnly`; nenhuma rota o devolve no corpo. Papel e e-mail da sessão são lidos do banco a cada requisição.
- **Formato:** `{ "error": "mensagem" }`. As rotas do cliente de dados (`/api/data/[table]`, `/api/storage/upload`, `/api/rpc/*`) usam `{ "data": null, "error": { "message": "..." } }`.

## Testes

`pnpm test:integration` chama estas Route Handlers diretamente (o mesmo código servido pelo Next.js), com o banco isolado `<MYSQL_DATABASE>_test`:

- **`src/app/api/auth-storage.integration.test.ts`:** cadastro, login, sessão, logout, storage e health.
- **`src/app/api/dados-admin.integration.test.ts`:** CRUD real com confirmação no banco, rotas administrativas, matriz de planos, páginas e documentos Puck.
- **`src/app/api/funcoes.integration.test.ts`:** IA e cotas, plano, score, avaliações, streaks, efemérides e webhook.
- **`src/app/api/seguranca.integration.test.ts`:** limites de tentativa de login e cadastro, contagem concorrente, sessão sem JWT e papel lido do banco.
- **`src/app/api/conta-email.integration.test.ts`:** troca do e-mail de login (senha, duplicidade, sessão reemitida).
- **`src/app/api/lgpd.integration.test.ts`:** consentimento, segregação dos dados do titular, registros fiscais, exportação e exclusão da conta.
