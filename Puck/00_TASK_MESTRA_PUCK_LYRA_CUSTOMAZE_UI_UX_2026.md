# Task Mestra — Puck no Lyra Customaze UI UX 2026

## 1. Propósito desta task mestra

Esta task mestra existe para organizar, com padrão profissional empresarial e nível máximo de detalhe, a adoção do **Puck** como base real do novo editor visual do **Lyra Customaze UI UX**.

O objetivo não é “instalar uma lib e dizer que virou Elementor”.

O objetivo real é:

- usar o Puck como engine visual séria;
- integrá-lo à Lyra com persistência real;
- preservar a stack real do projeto;
- construir uma experiência premium, clara, moderna e tendência 2026;
- preparar uma base reutilizável para outros apps compatíveis no futuro.

---

## 2. Posição honesta desta task

### 2.1. O que esta task é

- um plano de implementação real;
- uma matriz de execução operacional;
- um conjunto de 14 tarefas especializadas;
- um guia técnico, visual e arquitetural;
- uma trilha de entrega com validação real.

### 2.2. O que esta task não é

- não é um “feito”;
- não é um mock;
- não é uma promessa vazia de paridade com Elementor;
- não é um checklist superficial;
- não é documentação genérica.

---

## 3. Direção visual obrigatória para 2026

Toda implementação derivada desta task deve respeitar:

- tema claro como direção principal;
- visual premium e editorial;
- canvas limpo, sem poluição visual;
- UX de builder acolhedora, forte e profissional;
- design system coerente com a Lyra;
- aparência de produto sério, sofisticado e moderno de 2026;
- linguagem administrativa em pt-BR;
- controle fino de layout, viewport, conteúdo, slots e regras de edição;
- separação clara entre edição, preview, publicação e consumo público.

### 3.1. Tendências 2026 que esta task deve perseguir

- edição sobre componentes reais;
- controles responsivos por viewport;
- governança de design system;
- rich text inline no canvas;
- UX de inserção organizada por categorias;
- preview fiel ao frontend;
- política de permissões por superfície e por elemento;
- estrutura preparada para dynamic content;
- experiência premium para usuários não técnicos.

---

## 4. Regras técnicas não negociáveis

- não hardcodar segredo;
- não versionar a chave beta no repositório;
- não simular persistência;
- não simular publicação;
- não criar rota fake sem integração real;
- não criar editor desvinculado do consumo público;
- não liberar edição para quem não for admin;
- não afirmar paridade com Elementor sem comprovação.
